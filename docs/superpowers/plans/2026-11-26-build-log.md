# 제작 기록 저장 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 키우는 기체마다 제작 기록(박스를 연 시각, 등급별 도달 시각·도구별 토큰·사포로 채운 양·알 수 없는 양)을 쌓고, 완성하거나 내보낼 때 격납고 기록으로 옮긴다. 화면은 바꾸지 않는다.

**Architecture:** 순수 값 타입 `BuildLog`(새 파일)가 더하기, 등급 업 때의 분할, 수치 정규화를 맡는다. `MonState`와 `DexEntry`가 이 값을 선택 필드로 들고 다닌다(`prayers`가 옮겨지는 경로와 같다). `CompanionStore.applyUsage`가 증가분의 출처(`BuildIncrement`)를 받아 성장치와 기록을 함께 갱신한다. 성장 계산식은 건드리지 않는다.

**Tech Stack:** Swift 6, SwiftPM, XCTest, macOS 14+. 외부 의존성 추가 없음.

**Spec:** `docs/superpowers/specs/2026-11-25-build-log-design.md`

## Global Constraints

- 성장·등급 업·완성·재화는 변경 전과 똑같이 동작한다. **기존 테스트 파일을 수정하지 않고** 전부 통과해야 한다.
- 도구별 토큰은 실제로 쓴 토큰이다. 성장 난이도를 바꿔도 기록은 다시 계산하지 않는다.
- 갈래의 합이 `usedAtStage`와 같다고 가정하는 코드를 두지 않는다.
- 도구 키는 `UsageProvider.id` 문자열을 그대로 쓴다. 특정 도구 이름으로 가르는 분기를 만들지 않는다.
- 기록에 프롬프트, 파일 경로, 프로젝트 이름을 넣지 않는다.
- 기록이 깨져 읽을 수 없으면 기록만 `nil`이 되고 기체와 격납고 기록은 남는다.
- 수치 상한은 `SaveTransfer.maxTokenValue`(1_000_000_000_000_000)다.
- `SaveEnvelope.schemaVersion`은 2 그대로 둔다.
- 범위 밖: 기록을 보여주는 화면, `activeDexEntry`에 기록 싣기, 날짜별 내역.
- 브랜치 `feat/build-log`는 `origin/main`(6ed66f1)에서 만들었다. 작업 트리에 다른 작업의 미커밋 변경(`docs/gunpla/ideas.md`, `docs/gunpla/non-uc-roster.md`, `error.log`)이 있으므로 `git add`는 항상 경로를 지정하고, `git stash`·`reset`·`restore`·`checkout`·`clean`은 쓰지 않는다.
- 종 ID를 다시 쓰는 세이브 이전(`FullArmorUnicornMigration`)은 기록을 건드리지 않는다. 기록은 이 기능이 들어간 빌드에서만 생기고, 그 빌드는 상태를 읽을 때마다 이전을 먼저 수행하므로 기록에 옛 ID가 들어갈 수 없다.
- 커밋 메시지는 영어 Conventional Commits. `CLAUDE.md`의 결함 대응 프로토콜을 따른다.

```swift
/// Where an amount of growth came from.
enum BuildIncrement: Equatable, Sendable {
    case providers([String: Int])   // actual tokens, keyed by UsageProvider.id
    case sandpaper(Int)             // growth credits from sponge sandpaper
    case unattributed(Int)          // source unknown
    var total: Int { get }          // plain sum; what usedAtStage grows by
}

struct BuildStage: Codable, Sendable, Equatable {
    var speciesID: Int              // GunplaID (machine × grade)
    var reachedAt: Date?            // nil = unknown
    var tokensByProvider: [String: Int]
    var sandpaper: Int
    var unattributed: Int
    init(speciesID: Int, reachedAt: Date?, tokensByProvider: [String: Int] = [:],
         sandpaper: Int = 0, unattributed: Int = 0)
}

struct BuildLog: Codable, Sendable, Equatable {
    var openedAt: Date?             // nil = the record began mid-build
    var stages: [BuildStage]
    static func opened(speciesID: Int, at: Date) -> BuildLog
    static func resumed(speciesID: Int, banked: Int) -> BuildLog
    mutating func add(_ increment: BuildIncrement, to speciesID: Int)
    mutating func advance(from: Int, to: Int, banked: Int, threshold: Int, at: Date)
    func keeping(_ speciesIDs: [Int]) -> BuildLog
    func clamped(to limit: Int) -> BuildLog
}

// MonState: `var buildLog: BuildLog?`, init parameter `buildLog: BuildLog? = nil` (last)
// DexEntry: `var buildLog: BuildLog?`, init parameter `buildLog: BuildLog? = nil` (last)
```

이 태스크에서 정하는 동작:

- `opened`: 등급 하나, `openedAt`과 그 등급의 `reachedAt`이 같은 시각.
- `resumed`: 등급 하나, `openedAt`과 `reachedAt`은 `nil`, `unattributed`에 `banked`.
- `add`: `speciesID`가 같은 첫 등급 기록에 더한다. 없으면 `reachedAt: nil`인 등급 기록을 끝에 만들고 더한다. 0 이하의 양은 더하지 않고 키도 만들지 않는다.
- `advance`: 넘친 양은 `banked − threshold`다(0…`banked`로 자른다). `from` 등급의 갈래마다 `floor(값 × 넘친 양 / banked)`를 `to` 등급으로 옮기고 나머지를 남긴다. `to` 등급 기록이 없으면 `reachedAt: at`으로 만들고, 이미 있으면 그 기록에 더하되 `reachedAt`은 건드리지 않는다. 옮긴 양이 0인 도구는 `to`에 키를 만들지 않는다. `banked`가 0 이하면 아무것도 옮기지 않는다.
- `keeping`: `speciesID`가 목록에 있는 등급 기록만 남긴다. `openedAt`은 그대로.
- `clamped`: 모든 수치를 0…`limit`로 자른다.
- 세이브 읽기: `MonState`와 `DexEntry`의 `init(from:)`에서 `(try? c.decodeIfPresent(BuildLog.self, forKey: .buildLog)) ?? nil`.
- `BuildStage.speciesID`의 문서 주석에 한 줄을 남긴다: `chainOrder`나 `pathIDs`의 종 ID를 다시 쓰는 세이브 이전(`FullArmorUnicornMigration` 참고)을 새로 만들면 이 ID도 함께 써야 한다.

카탈로그가 바뀌어 저장된 경로가 다시 맞춰지는 경우(`normalizedEvolutionState`)를 위한 별도 코드는 두지 않는다. `add`와 `advance`가 등급을 ID로 찾고 없을 때만 만들기 때문에, 현재 등급이 이미 적힌 등급으로 되돌아가도 그 기록에 이어서 쌓인다.

@testable import PokeTokenBar

final class BuildLogTests: XCTestCase {
    private let t0 = Date(timeIntervalSince1970: 1_700_000_000)
    private let t1 = Date(timeIntervalSince1970: 1_700_086_400)
    private let sd = 100_010, hg = 100_012

    private func stage(_ id: Int, _ tokens: [String: Int] = [:], sandpaper: Int = 0, unattributed: Int = 0,
                       at: Date? = nil) -> BuildStage {
        BuildStage(speciesID: id, reachedAt: at, tokensByProvider: tokens, sandpaper: sandpaper,
                   unattributed: unattributed)
    }

    func test_openedStartsOneStageStampedWithTheOpenTime() {
        XCTAssertEqual(BuildLog.opened(speciesID: sd, at: t0),
                       BuildLog(openedAt: t0, stages: [stage(sd, at: t0)]))
    }

    func test_resumedHoldsTheBankedAmountAsUnattributedWithNoTimes() {
        XCTAssertEqual(BuildLog.resumed(speciesID: hg, banked: 500),
                       BuildLog(openedAt: nil, stages: [stage(hg, unattributed: 500)]))
    }

    func test_addAccumulatesEachSourceInItsOwnBucket() {
        var log = BuildLog.opened(speciesID: sd, at: t0)
        log.add(.providers(["a": 100, "b": 40, "zero": 0]), to: sd)
        log.add(.providers(["a": 5]), to: sd)
        log.add(.sandpaper(7), to: sd)
        log.add(.unattributed(3), to: sd)
        XCTAssertEqual(log.stages, [stage(sd, ["a": 105, "b": 40], sandpaper: 7, unattributed: 3, at: t0)])
        XCTAssertEqual(BuildIncrement.providers(["a": 100, "b": 40]).total, 140)
        XCTAssertEqual(BuildIncrement.sandpaper(7).total, 7)
        XCTAssertEqual(BuildIncrement.unattributed(3).total, 3)
    }

    func test_addCreatesTheStageWhenItIsMissing() {
        var log = BuildLog.opened(speciesID: sd, at: t0)
        log.add(.providers(["a": 1]), to: hg)
        XCTAssertEqual(log.stages, [stage(sd, at: t0), stage(hg, ["a": 1])])
    }

    /// The spec's example: threshold 1,000, banked 1,200, so one sixth of every bucket moves on.
    func test_advanceMovesTheOverflowShareAndStampsTheNewGrade() {
        var log = BuildLog(openedAt: t0, stages: [stage(sd, ["claude": 900, "codex": 300], at: t0)])
        log.advance(from: sd, to: hg, banked: 1_200, threshold: 1_000, at: t1)
        XCTAssertEqual(log.stages, [stage(sd, ["claude": 750, "codex": 250], at: t0),
                                    stage(hg, ["claude": 150, "codex": 50], at: t1)])
    }

    func test_advanceConservesEveryBucketWhenTheShareDoesNotDivide() {
        var log = BuildLog(openedAt: t0, stages: [
            stage(sd, ["claude": 100, "codex": 7], sandpaper: 3, unattributed: 1, at: t0)])
        log.advance(from: sd, to: hg, banked: 111, threshold: 100, at: t1)   // 11/111 moves, rounded down
        XCTAssertEqual(log.stages, [stage(sd, ["claude": 91, "codex": 7], sandpaper: 3, unattributed: 1, at: t0),
                                    stage(hg, ["claude": 9], at: t1)])
    }

    /// After a difficulty change the buckets no longer add up to the banked growth.
    func test_advanceUsesBankedGrowthNotTheBucketSum() {
        var log = BuildLog(openedAt: t0, stages: [stage(sd, ["claude": 560], at: t0)])
        log.advance(from: sd, to: hg, banked: 110, threshold: 100, at: t1)
        XCTAssertEqual(log.stages, [stage(sd, ["claude": 510], at: t0), stage(hg, ["claude": 50], at: t1)])
    }

    func test_advanceAtTheTokenCeilingDoesNotTrap() {
        let top = SaveTransfer.maxTokenValue
        var log = BuildLog(openedAt: nil, stages: [stage(sd, ["a": top], sandpaper: top, unattributed: top)])

    }

    func test_advanceWithNoOverflowOnlyOpensTheNewStage() {
        var log = BuildLog(openedAt: t0, stages: [stage(sd, ["a": 1_000], at: t0)])
        log.advance(from: sd, to: hg, banked: 1_000, threshold: 1_000, at: t1)
        XCTAssertEqual(log.stages, [stage(sd, ["a": 1_000], at: t0), stage(hg, at: t1)])

    func test_advanceIntoAnExistingStageMergesAndKeepsItsReachedAt() {
        var log = BuildLog(openedAt: t0, stages: [stage(sd, ["a": 1_200], at: t0), stage(hg, ["a": 10], at: t0)])
        log.advance(from: sd, to: hg, banked: 1_200, threshold: 1_000, at: t1)
        XCTAssertEqual(log.stages, [stage(sd, ["a": 1_000], at: t0), stage(hg, ["a": 210], at: t0)])

        let log = BuildLog(openedAt: t0, stages: [stage(sd, ["a": 1], at: t0), stage(hg, ["a": 2], at: t1)])
        XCTAssertEqual(log.keeping([sd]), BuildLog(openedAt: t0, stages: [stage(sd, ["a": 1], at: t0)]))

    func test_clampedBoundsNegativeAndHugeNumbers() {

/// floor(value × share / banked). Both factors can reach 10^15, so the product needs full width.
private static func portion(of value: Int, share: Int, banked: Int) -> Int {
    guard value > 0, share > 0, banked > 0 else { return 0 }
    let product = value.multipliedFullWidth(by: min(share, banked))
    return banked.dividingFullWidth(product).quotient
}

이 태스크에서 정하는 동작:

- `applyUsage(_ increment:)`는 순서대로: 키우는 기체가 없으면 반환 → 기록이 없으면 `.resumed(speciesID: currentID, banked: usedAtStage)`로 만든다(더하기 전) → `usedAtStage += increment.total` → `buildLog.add(increment, to: currentID)` → 기존 등급 판정 루프. 라인이 없어 루프를 못 도는 경우에도 앞의 세 단계는 수행한다.
- 등급이 오를 때마다 `buildLog.advance(from: 이전 등급 ID, to: 새 등급 ID, banked: 오르기 직전의 usedAtStage, threshold: 그때의 임계, at: clock())`.
- `update`의 두 경로는 0보다 큰 도구별 증가분을 `[String: Int]`로 모아 `applyUsage(.providers(...))`로 넘긴다. 박스 단계(`eggUsage`)와 `usedSinceInstall`에 더하는 합계는 지금과 같다.
- `hatchCore`는 `MonState`를 만들 때 `buildLog: .opened(speciesID: line.baseID, at: clock())`를 넘긴다. 넘어온 양은 지금의 정수 호출 그대로 둔다(알 수 없는 양이 된다).
- `useRareCandy`는 `applyUsage(.sandpaper(xp))`.
- `graduate`는 `DexEntry`에 `buildLog: a.buildLog`. `releasedDexEntry`와 `retireUnservableActive`는 `buildLog: a.buildLog?.keeping(남기는 등급 ID 목록)`.
- `setGrowthDifficulty`와 `rescaleBankedGrowth`는 바꾸지 않는다.

    private func store(seed: CompanionState? = nil, growth: Double = 1) throws -> CompanionStore {
        let url = FileManager.default.temporaryDirectory.appendingPathComponent("build-log-\(UUID().uuidString).json")
        if let seed { try JSONEncoder().encode(seed).write(to: url) }
        let defaults = try XCTUnwrap(UserDefaults(suiteName: "build-log-\(UUID().uuidString)"))
        defaults.set(growth, forKey: "growthDifficulty")
        let clock = clock
        return CompanionStore(provider: catalog, clock: { clock.now }, fileURL: url,
                              rng: SeededRNG(seed: 7), defaults: defaults)
    }

    /// A save that already has its install baseline: both tools known, nothing claimed today.
    private func seeded(_ edit: (inout CompanionState) -> Void = { _ in }) -> CompanionState {
        var state = CompanionState()
        state.installBaselineSet = true
        state.lastDate = "d1"
        state.claimedTodayTokensByProvider = ["a": 0, "b": 0]
        edit(&state)
        return state
    }

    private func raising(usedAtStage: Int = 0) -> MonState {
        MonState(baseID: sd, pathIDs: [sd], plannedPathIDs: path, stageIndex: 0, usedAtStage: usedAtStage,
                 rarity: .rare, totalForms: path.count)
    }

    private func use(_ s: CompanionStore, _ today: [String: Int], date: String = "d1") {
        s.update(todayTokensByProvider: today, todayDate: date, monthTotal: 0,
                 burnTier: .idle, limitWarning: false, hasUsageData: true)
    }

    private func log(_ s: CompanionStore) throws -> BuildLog { try XCTUnwrap(s.state.active?.buildLog) }

    private func total(_ log: BuildLog, _ tool: String) -> Int {
        log.stages.reduce(0) { $0 + ($1.tokensByProvider[tool] ?? 0) }
    }
