# 제작 기록 카드 — 설계 문서

- 날짜: 2026-11-26
- 상태: 승인 (2026-11-26)
- 선행 작업: `docs/superpowers/specs/2026-11-25-build-log-design.md` (제작 기록 저장, 브랜치 `feat/build-log`, 아직 `main`에 없음)
- 표기: **[결정]** 은 사용자가 정한 것, **[작성자 판단]** 은 작성자가 채운 것이다. 뒤의 것은 검토에서 바꿀 수 있다.

## 1. 의도와 이유

1단계에서 기체마다 제작 기록(박스 개봉 시각, 등급별 도달 시각, 등급별·도구별 토큰, 스펀지 사포 양)을
세이브에 쌓기 시작했다. 지금은 쌓이기만 하고 어디에서도 보이지 않는다. 이 작업은 그 기록을 화면에
보여 준다. 기체 하나를 만드는 데 며칠이 걸렸고 어느 등급에서 얼마를 썼는지 돌아보는 재미가 목적이고,
3단계(카드를 이미지로 복사)의 바탕이 된다.

## 2. 목표 / 비목표 / 반목표

**목표**

- **[결정]** 기체 상세 화면(`PokemonDetailView`)에 선택된 제작의 기록을 등급별 표 카드로 보여 준다.
- **[결정]** 키우는 중인 기체의 기록도 같은 카드로 보여 준다.
- **[결정]** 제작 기록 목록에서 행을 눌러 들어오면 그 행의 제작이 선택된 채로 열린다.
- **[결정]** "놓아주다" 계열 문구를 건프라에 맞는 말로 바꾼다.

**비목표 (이번 범위 아님)**

- 카드를 이미지로 복사·공유하기(3단계).
- 제작 기록 목록(`DexEntryRow`)의 행에 요약을 넣거나 행을 펼치는 것.
- 지나온 등급의 참고 페이지(개체가 없는 페이지)에 기록을 띄우는 것.
- 저장되는 기록의 모양이나 쌓이는 규칙을 바꾸는 것. 이 작업은 읽기만 한다.
- 도구별로 다른 색을 쓰는 것, 막대 이외의 차트.

**반목표 (기술적으로 돌아가도 이러면 실패)**

- 카드 때문에 팝오버가 좌우로 넓어지거나 잘린다(`PopoverMetrics.scrollContentWidth` 초과).
- 손편집됐거나 오래된 세이브의 기록(등급 누락, 경로에 없는 등급, 같은 등급 ID 중복)에서 앱이 죽는다.
- 다른 제작의 기록이 보인다(같은 기체를 여러 번 만든 경우).
- 기록 전 성장치나 출처를 모르는 양이 특정 도구의 토큰처럼 보인다.
- 특정 도구 ID 리터럴로 분기한다(`CLAUDE.md` 확장 규약).
- 키우는 중 카드를 갱신하려고 상시 타이머나 애니메이션을 돌린다.

## 3. 제약

- macOS 14+, SwiftUI. 상세 화면은 높이 520의 세로 스크롤 영역 안에 있고, 그 안에서 쓸 수 있는 폭은
  `PopoverMetrics.scrollContentWidth`다. 폭을 넘는 자식 하나가 팝오버 전체를 넓힌다.
- 지원 언어는 한국어·영어·일본어 셋이다(`AppLanguage`). 건담 문구는 3개 언어 `t(ko, en, ja)`를 쓴다.
- `CompanionStore`는 도구의 표시 이름을 모른다. 이름은 `UsageStore.registeredProviders`
  (`UsageProvider.displayName`)에 있고, `PopoverView`가 두 스토어를 모두 갖고 있다.
- 키우는 중인 기체는 격납고 목록에 화면용 항목(`CompanionStore.activeDexEntry`)으로 합성되며 저장되지
  않는다. 지금은 이 항목에 기록이 실려 있지 않다.
- 상세 화면의 개체 목록은 `pokemonIndividuals(speciesID:)`, 곧 마지막 등급이 그 페이지의 등급인 제작들이다.
  기본 선택은 키우는 중인 것, 그다음 가장 최근 것이다.
- 기록의 저장 모양은 테스트(`test_recordWrittenByThisReleaseStillDecodes`)로 고정돼 있다.
- 저장소 규칙: 전체 게이트(`scripts/test-gate.sh`), 화면이 달라지는 PR은 이미지 필수, 커밋·PR은 영어.

## 4. 접근 방식 (검토한 안)

| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 기체 상세 화면** | 개체 선택 아래, 프로필 카드 위에 카드를 둔다 | 격납고 칸·홈의 기체 그림·목록 행 세 경로가 모두 이 화면으로 온다. 3단계에서 기체 그림·이름·기록이 한 화면에 있다. 등급이 많으면 스크롤이 생긴다 |
| B. 제작 기록 목록의 행 펼침 | 행 안에 표를 펼친다 | 행 하나가 제작 한 번이라 헷갈리지 않는다. 격납고 칸이나 홈에서 바로 갈 수 없고, 펼치면 목록 스크롤이 크게 움직인다 |
| C. 요약 한두 줄 | 등급별 표 없이 기간·총량·비율만 | 짧지만 1단계에서 저장한 등급별 내용이 화면에 나오지 않는다 |

**[결정]** A, 등급별 표.

## 5. 카드

### 5.1 위치와 표시 조건

- **[결정]** 상세 화면에서 개체 선택 메뉴 바로 아래, 프로필 카드(형식번호·소속·작품) 위.
- **[결정]** 선택된 개체가 없거나 그 개체에 기록이 없으면 카드를 그리지 않는다. 이 변경 전에 완성한
  기체는 모두 기록이 없다.
- **[작성자 판단]** 기록은 있지만 아래 5.2의 어느 줄에도 해당하는 등급 기록이 없으면 역시 그리지 않는다.

### 5.2 줄

- **[결정]** 그 제작이 거쳐 온 등급마다 한 줄. 줄 순서는 `chainOrder` 순서다.
- **[작성자 판단]** "거쳐 온 등급"은 `chainOrder` 전체다. 키우는 중인 항목의 `chainOrder`(`pathIDs`)도
  도달한 등급만 담는다(개봉 때 첫 등급 하나, 등급 업마다 하나씩 붙는다). 도달하지 않은 등급이 들어 있는
  경우는 손편집 세이브뿐이라 따로 자르지 않는다.
- 한 줄의 내용, 왼쪽부터:
  1. 등급 이름(`GunplaGrade.label`).
  2. 그 등급에 도달한 날짜(`reachedAt`). 없으면 "—".
  3. 막대.
  4. 그 등급에서 쓴 양 = 도구별 토큰 합 + 스펀지 사포 + 출처를 모르는 양. `TokenFormatter.compact` 표기.
- 그 등급의 기록이 없으면(기록 전에 지나간 등급) 날짜와 양을 "—"로 두고 막대를 그리지 않는다.
- **[작성자 판단]** 등급 기록은 ID로 찾는다. 같은 ID가 두 번 나오면 앞의 것을 쓴다
  (`BuildLog`가 쓰는 규칙과 같다). 줄에 없는 등급의 기록은 무시하고 총량에도 넣지 않는다.
  `stages`로 `Dictionary(uniqueKeysWithValues:)`를 만들지 않는다.

### 5.3 막대

- **[결정]** 길이는 가장 많이 쓴 줄을 꽉 찬 길이로 두고 나머지는 그에 비례한다. 모든 줄이 0이면 막대가 없다.
- **[결정]** 한 막대를 출처별로 나눠 칠한다: 실제 토큰(파랑), 스펀지 사포(주황), 출처를 모르는 양(회색).
- **[작성자 판단]** 칠하는 순서는 회색, 파랑, 주황이다. 색은 라이트·다크 모두에서 읽혀야 한다.

### 5.4 머리줄

상태에 따라 달라진다. 한 줄에 안 들어가면 두 줄로 나눈다. 글자가 잘리면 안 된다.

| 상태 | 판정 | 내용 (한국어 예) |
|---|---|---|
| 완성 | 키우는 중도 중단도 아님 | `개봉 2026. 11. 27. → 완성 2026. 12. 14. · 17일 · 총 2.41B` |
| 키우는 중 | `store.isActiveDexEntry` | `개봉 2026. 11. 27. · 6일째 · 지금까지 519.9M`, 제목 옆에 "키우는 중" 배지 |
| 제작 중단 | `entry.isReleased` | `개봉 2026. 11. 20. → 중단 2026. 11. 26. · 6일 · 총 310.2M` |
| 도중부터 기록 | `openedAt == nil` | `HG 도중부터 기록 → 완성 2026. 12. 20. · 총 1B` (기간은 표시하지 않는다) |

- 끝난 시각은 `caughtAt`이다(완성 시각 또는 중단 시각). 없으면 그 부분을 생략한다.
- "도중부터 기록"의 등급은 줄 순서에서 기록이 있는 첫 등급이다. 이 상태가 키우는 중이나 중단과 겹치면
  `개봉 …` 자리만 바꾸고 나머지는 그 상태의 규칙을 따른다.
- **[결정]** 총량은 줄을 모두 더한 값이며 스펀지 사포를 포함한다.
- **[결정]** 키우는 중인 줄(마지막 줄)은 등급 이름을 강조색으로 쓴다.
- **[작성자 판단]** 기간은 달력 날짜 차이로 센다(`Calendar.current`). 끝난 제작은 차이가 0이면 "당일",
  아니면 "N일". 키우는 중은 "N+1일째". 오늘 날짜는 그릴 때 한 번 읽는다.
- **[작성자 판단]** 날짜는 앱 언어 로캘의 숫자 표기다. 머리줄은 연도를 포함하고(개체 선택 메뉴와 같은
  `Date.FormatStyle(date: .numeric, time: .omitted)`), 줄은 월·일만 쓴다.

### 5.5 아랫줄

- **[결정]** 출처별 합계를 나열한다: 도구들, 스펀지 사포, 출처를 모르는 양. 0인 것은 생략한다.
  각 항목 앞에 막대와 같은 색의 점을 둔다.
- **[작성자 판단]** 도구는 양이 많은 순, 같으면 이름순이다. 사포와 출처를 모르는 양은 그 뒤에 온다.
- **[결정]** 도구 이름은 설정에 나오는 표시 이름이다. 더는 등록돼 있지 않은 도구는 저장된 ID를 그대로 쓴다.
- **[작성자 판단]** 출처를 모르는 양의 이름은 기록이 어떻게 시작됐는지에 따라 다르다.
  `openedAt == nil`이면 "기록 전"(기록이 시작되기 전에 쌓여 있던 성장치이고 토큰이 아니다),
  아니면 "개봉 전 사용분"(박스를 열 때 넘쳐서 이월된 사용량이다).

### 5.6 툴팁

- **[결정]** 등급 줄에 마우스를 올리면 그 등급의 출처별 양이 툴팁으로 나온다. 아랫줄과 같은 이름·순서이고
  0인 것은 생략한다.
- **[작성자 판단]** 같은 문장을 그 줄의 접근성 설명에도 쓴다.

### 5.7 문구

카드 제목은 기존 `catchLogTitle`("제작 기록"), "키우는 중"은 기존 `dexRaising`, 스펀지 사포는 기존 아이템
이름을 다시 쓴다. 새 문구는 **[작성자 판단]** 이다.

| 용도 | 한국어 | 영어 | 일본어 |
|---|---|---|---|
| 개봉 | 개봉 {날짜} | Opened {date} | 開封 {date} |
| 완성 | 완성 {날짜} | Completed {date} | 完成 {date} |
| 중단 | 중단 {날짜} | Stopped {date} | 中断 {date} |
| 기간(끝남) | {n}일 / 당일 | {n} days (1 day) / Same day | {n}日 / 当日 |
| 기간(키우는 중) | {n}일째 | Day {n} | {n}日目 |
| 총량 | 총 {양} | Total {amount} | 合計 {amount} |
| 지금까지 | 지금까지 {양} | {amount} so far | これまで {amount} |
| 도중부터 | {등급} 도중부터 기록 | Recorded from mid-{grade} | {grade}の途中から記録 |
| 기록 전 | 기록 전 | Before record | 記録前 |
| 개봉 전 | 개봉 전 사용분 | Before unboxing | 開封前 |

## 6. 연결 수정

### 6.1 목록에서 누른 제작으로 열기

- **[결정]** 제작 기록 목록의 행에서 그 행의 **마지막 등급** 그림을 눌러 상세 화면을 열면, 그 행의 제작이
  선택된 채로 열린다.
- **[작성자 판단]** 일반/전용기 외형은 따로 맞추지 않는다. `PokemonDetailView`는 표시 중인 외형으로 개체
  목록을 거르지만, 전용기는 자기 ID를 가진 별도 기체(`variantOf`)라 한 페이지에 일반 제작과 전용기 제작이
  섞이지 않는다. 손편집 세이브에서만 생기는 경우이므로 가드도 테스트도 두지 않는다.
- 그 밖의 경로(격납고 칸, 홈의 기체 그림, 행의 앞 등급 그림)는 지금과 같이 기본 선택을 따른다.
- 이전에 누른 행의 선택이 다른 경로로 연 상세 화면에 남아 있으면 안 된다.

### 6.2 키우는 중인 기체에 기록 연결

- **[결정]** `activeDexEntry`가 `active.buildLog`를 싣는다. 이 항목은 화면용이며 저장되지 않는다.
- 사용량이 들어와 기록이 바뀌면 열려 있는 카드의 숫자도 따라 바뀐다(`CompanionStore`의 관찰로 충분하다).

### 6.3 도구 이름 전달

- **[작성자 판단]** `PopoverView`가 `UsageStore.registeredProviders`로 만든 "ID → 표시 이름" 사전을
  격납고 화면을 거쳐 카드까지 내려 준다. 카드는 도구 ID를 그 사전으로만 해석한다.

## 7. "놓아주다" 문구

- **[결정]** 포켓몬에서 온 "놓아주다"를 건프라에 맞는 말로 바꾼다.
- **[작성자 판단]** 새 말은 **"제작 중단"** 이다. 박스를 새로 사면 지금 기체의 제작이 멈추고, 거기까지 만든
  등급은 격납고에 남는다는 실제 동작과 맞는다. 검토한 다른 후보는 "미완성", "보관"이다.
- **[작성자 판단]** 한국어는 "놓아주다"가 나오는 모든 문구를 바꾼다. 카드와 목록 배지가 같은 말을 써야 하기
  때문이다. 영어·일본어는 배지만 바꾼다. 영어 "Released"는 "released grades"(출시 등급)와 겹치고, 일본어
  "逃がした"는 생물을 놓아준다는 뜻이다. 영어·일본어 상점 문구("Send off", "手放す")는 그대로 둔다.

| 키 | 지금 (ko) | 바꾼 뒤 (ko) |
|---|---|---|
| `dexReleased` | 놓아줌 | 제작 중단 |
| `eggDescription` (기본) | 지금 기체를 놓아주고 새 건프라 박스로 다시 시작해요. | 지금 기체 제작을 중단하고 새 건프라 박스로 다시 시작해요. |
| `eggDescription` (등급 박스) | 지금 기체를 놓아주고 {r} 이상이 확정으로 나오는 박스를 받아요. | 지금 기체 제작을 중단하고 {r} 이상이 확정으로 나오는 박스를 받아요. |
| `eggReleaseNote` | 놓아준 기체도 격납고에 남고, … | 제작을 중단한 기체도 격납고에 남고, … (뒤는 그대로) |
| `eggConfirm` | {기체}을 놓아주고 {박스}로 바꿀까요? | {기체} 제작을 중단하고 {박스}로 바꿀까요? |

## 8. 검증

- **표시 규칙 단위 테스트.** 뷰에서 떼어 낸 순수 로직으로 다음을 각각 확인한다: 완성, 키우는 중(아직
  도달하지 않은 등급은 줄이 없다), 제작 중단, 도중부터 기록(앞 등급 "—", 머리줄의 등급), 줄에 없는 등급의
  기록 무시, 같은 등급 ID 중복(죽지 않고 앞의 것 사용), 모든 줄이 0, 기록 없음(카드 없음),
  도구 이름 대체(없는 도구는 ID), 출처를 모르는 양의 두 가지 이름, 기간 세기(당일·N일·N일째).
- **연결 테스트.** 같은 기체·같은 등급 제작이 둘일 때 오래된 행으로 열면 오래된 제작이 선택된다.
  격납고 칸으로 열면 기본 선택이다. 키우는 중인 항목이 기록을 싣고, 사용량을 넣으면 카드 숫자가 바뀐다.
- **렌더 테스트.** `IndividualPickerRenderingTests`와 같은 방식으로 상세 화면을 띄워 기록이 있으면 카드가
  있고 없으면 없는지, 내용 폭이 `PopoverMetrics.scrollContentWidth`를 넘지 않는지 확인한다(등급 8개,
  세 언어). 같은 테스트가 환경변수로 지정한 폴더에 PNG를 떨어뜨려 PR 이미지로 쓴다.
- **문구.** 한국어 사용자 문구에 "놓아"가 남지 않았는지 확인하는 테스트.
- **게이트.** `./scripts/test-gate.sh` 통과. 순수 로직 파일은 `LOGIC_CORE`에 넣고, 새 조건 분기는
  `llvm-cov show --show-regions`로 `^0`이 없는지 본다.
- **PR 이미지.** 상세 화면(전·후), 제작 기록 목록의 배지(전·후), 상점 박스 카드 문구(전·후).
  샘플 데이터 렌더링임을 밝힌다.
- **실제 앱.** 키우는 중인 기체로 홈 → 기체 그림 → 카드가 보이는지 한 번 확인한다.
