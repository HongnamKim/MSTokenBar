# 건프라 토큰바 (가칭) — 설계 문서

- 작성일: 2026-11-22
- 상태: 초안 (사용자 승인 전)
- 원본: [chattymin/PokeTokenBar](https://github.com/chattymin/PokeTokenBar) (MIT, Swift 6, macOS 14+)

> 표기: **[결정]** = 사용자가 정한 것, **[제안]** = 대화 중 제안하고 사용자가 "다 맞아요"로 확인한 것,
> **[작성자 판단]** = 이 문서를 쓰면서 정한 것 (사용자가 검토 시 바꿀 수 있음).

## 1. 의도와 이유

사용자는 건담 팬이다. PokeTokenBar는 AI 코딩 도구의 토큰 사용량으로 포켓몬을 부화·진화·수집하는
macOS 메뉴바 앱인데, 이 수집 대상을 **건프라**로 바꾼 버전을 만들고 싶다.
급하지 않은 장기 취미 프로젝트이고, 도트 스프라이트는 천천히 채워 나간다.
**무료 + 오픈소스, 비상업 팬 프로젝트**로 공개 배포할 수 있다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 원본의 사용량 추적(16개 도구, 공식 한도, 비용, 메뉴바, 플로팅 펫, 상점, 가방)을 그대로 유지한다.
- 수집 대상: 우주세기 건담 기체. 진화 = 건프라 등급 상승.
- 격납고(도감)를 작품별로 나누고, 등급 단계마다 따로 기록한다.
- 기체마다 오리지널 도트 스프라이트에 반복 애니메이션.

**비목표 (이번 범위 아님)**
- 우주세기 외 작품(SEED, 00, 철혈 등) — 샘플이 돌아간 뒤 데이터만 추가하는 방식으로 확장.
- 윈도우/리눅스 지원.
- 원본 PokeTokenBar 세이브 가져오기.

**반목표 (기술적으로 돌아가도 이러면 실패)**
- 공식 일러스트·박스아트·게임 스프라이트를 따거나 트레이싱한 이미지 사용.
- 앱 이름·아이콘에 「건담」「건프라」 상표나 반다이/선라이즈 로고 사용.
- 수익화(후원 버튼 포함).
- 실제로 존재하지 않는 키트(예: "PG 짐")가 진화 경로에 등장.

## 3. 제약

- 건담에는 PokéAPI 같은 공개 데이터/이미지 API가 없다 → **모든 데이터와 스프라이트를 앱에 내장**한다(네트워크 불필요).
- 기체 디자인은 저작물, 「건담」「건프라」는 상표 → 반목표 참고. README에 면책 문구
  ("비공식 팬 프로젝트, 반다이남코·선라이즈와 무관, 모든 권리는 원저작자에게").
- 데이터에는 사실 정보(형식번호, 출시 등급, 등장 작품)만 담고, 위키 설명 문장을 복사하지 않는다.
- 원본 저장소의 규칙(`CLAUDE.md`, 확장 규약, 결함 대응 프로토콜)은 포크에서도 유지한다.

## 4. 접근 방식 (검토한 안)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 원본 포크 후 포켓몬 층 교체** ✅ 선택 | 사용량·UI·상점은 유지, PokéAPI/스프라이트/포켓몬 전용 개념만 교체 | 16개 도구 사용량 읽기·공식 한도 등 원본의 가장 큰 자산을 그대로 얻음, 업스트림 업데이트 수용 가능 | 포켓몬 개념이 코드 곳곳에 섞여 있어 걷어낼 양이 많음 (`CompanionStore` 2,300줄 등) |
| B. 새 메뉴바 앱 | 처음부터 작게 | 구조가 깔끔 | 사용량 읽기를 다시 만들어야 하고 지원 도구가 크게 줄어듦 |

사용자가 **A**를 골랐다. 윈도우/리눅스 포크(Tauri 등)는 사용자가 macOS라 제외.

## 5. 게임 규칙

### 5.1 기체와 이로치
- **[결정]** 형식이 다른 기체는 각각 별도 기체 (자쿠 II, 자쿠 II 개, 구프, 돔 …).
- **[결정]** **전용기는 기본기의 이로치**. 예: 샤아 전용 자쿠 = 자쿠 II의 이로치.
- 이로치가 뜨면 전용기 후보 전체에서 하나를 고른다 (개봉 순서는 5.3).
- **[제안]** 기본기 키트가 없는 전용기는 그냥 별도 기체(일반 후보)로 취급.
- 이로치 확률은 원본보다 높이고, 「빛나는 부적」 대신 도색 공구 세트로 올린다 (5.7).

### 5.2 진화 = 건프라 등급
- **[결정]** 등급 순서: **SD → MGSD → HG → RG → MG → PG** (6단계).
- **[결정]** 기체마다 **실제로 출시된 등급만** 거친다. 출시 안 된 단계는 건너뜀.
  MG만 나온 기체는 MG에서 시작해 MG로 끝난다(1단계).
- **[결정]** 이로치(전용기)는 기본기와 무관하게 **자기 키트가 나온 등급**만 따라간다.
- **[제안]** 등급 판정:
  - SD = BB전사, SD EX-스탠다드, SDCS 등 SD 계열 전부
  - HG = HGUC, HG 디 오리진, HG 썬더볼트 등 1/144 HG 계열 전부
  - MG Ver.2.0 / Ver.Ka 등 같은 등급의 여러 버전은 한 단계
  - PG = PG, PG 언리쉬드
  - 프리미엄 반다이 한정 키트도 출시로 인정
- **[작성자 판단]** 단계별 성장 임계값은 원본 `PokemonBalance.phaseThreshold`(레어도별 졸업 총량을 단계 수로 분배)를
  그대로 쓴다. 단계 수(k)가 1~6으로 달라져도 공식이 처리한다.

### 5.3 부화 (박스 개봉)
- 알 → **건프라 박스**. 토큰을 쓰면 개봉(부화)된다.
- **[결정]** **중복 없음**: **졸업한(최종 등급까지 키운) 기체**는 다시 나오지 않는다.
  (원본은 `CollectionWeight`로 중복 가중치를 절반으로만 줄인다 → 이 부분을 "후보에서 제외"로 바꾼다.)
- **[결정]** 졸업 전에 내보낸 기체(새 박스를 사서 보낸 경우)는 다시 나올 수 있고, 다시 나오면
  **지난번에 도달한 등급부터 시작**한다. 예: HG까지 키우다 보낸 기체 → 다음에 HG로 개봉되어 RG부터 이어서 성장.
  도달 등급은 격납고 기록(기체별 최고 도달 등급)에서 계산한다.
- **[결정]** **개봉 순서: 이로치 여부를 먼저 굴리고, 그다음 기체를 고른다.**
  1. 이로치 롤 (확률은 5.7 도색 공구 세트)
  2. 이로치면 → 아직 졸업 안 한 **전용기** 후보에서, 아니면 → 아직 졸업 안 한 **일반 기체** 후보에서 고른다.
  3. 후보 안에서는 레어도 가중치(높을수록 드물게)와 박스의 등급 보증을 적용.
  - 따라서 일반 자쿠 II를 졸업해도 샤아 전용 자쿠는 계속 얻을 수 있고, 그 반대도 마찬가지(서로 막지 않음).
  - 전용기 후보 레코드가 데이터의 `variantOf`로 기본기와 연결되어 있지만, 개봉에서는 독립된 후보로 취급한다.
  - **[작성자 판단]** 고른 쪽 후보가 비어 있으면 다른 쪽 후보에서 고른다. 양쪽 다 비면(= 전용기 포함 전부 졸업) 중복 허용 단계.
  - **[작성자 판단]** 전용기는 데이터에 자기 `rarity`를 가진다(성장 비용·박스 보증 판정에 사용).
- **[제안]** 전부 졸업한 뒤부터 중복 허용.
- **[작성자 판단]** 등급 보증 박스(언커먼/레어)의 후보가 모두 졸업으로 비면, 상점에서 그 박스를 비활성화하고
  "이 등급 이상은 모두 모았어요"를 표시한다. (원본은 후보 없는 알을 계속 재시도하는데, 중복 없음 규칙에선 그 상태가 전부 모으기 전에 생길 수 있다.)

### 5.4 레어도
- **[제안]** 원본은 포획률로 레어도를 정하지만, 여기서는 **기체의 역할**로 데이터에 직접 지정:
  - 커먼: 양산기 (자쿠 II, 짐 …)
  - 언커먼: 지휘관기·커스텀기
  - 레어: 주역기·라이벌기
  - 레전더리: 최종 결전기급 (뉴 건담, 사자비, 유니콘 …)

### 5.5 격납고 (도감)
- **[결정]** 진화 중간 단계도 모두 등록. RX-78-2를 PG까지 키우면 SD·MGSD·HG·RG·MG·PG 6칸.
- **[결정]** 원본의 지역(칸토·성도…) 필터 자리에 **작품별 카테고리**.
- **[제안]** 작품 하나를 다 모으면 **작품 완성 배지** (원본 지역 완성 배지 대응).
- 격납고 셀은 기체 단위, 셀 안에 보유 등급 표시. 상세 화면에 등급별 기록.
- 「캐치 로그」(개체별 기록)는 원본처럼 유지.

### 5.6 샘플 범위 (첫 데이터셋)
- **[결정]** **우주세기 애니메이션에 등장**했고 **건프라로 출시된** 기체만.
- **[제안]** 포함 작품: 퍼스트, 08소대, 0080, 0083, Z, ZZ, 역습의 샤아, F91, V, UC, NT, 섬광의 하사웨이,
  썬더볼트, 디 오리진, 이글루, 쿠쿠루스 도안의 섬 등.
- **[제안]** MSV·게임·만화 전용 기체 제외 (예: 조니 라이덴 자쿠). 지쿠악스(GQuuuuuuX) 같은 애매한 작품은 일단 제외.
- **[결정]** 기체는 **첫 등장 작품 하나**에만 속한다 (자쿠 II = 퍼스트).
- **[결정]** 디 오리진판·썬더볼트판처럼 **디자인과 키트가 다른 리디자인은 별도 기체**이고, 그 작품 소속.
- **[결정]** 첫 공개판은 우주세기 15개 작품의 기체 126기를 수록한다. [확정 명단](../../gunpla/initial-roster.md)

### 5.7 아이템·상점 (원본 기능 유지, 이름만 교체)
| 원본 | 건프라판 | 기능 |
|---|---|---|
| 이상한 사탕 | **[결정] 스펀지 사포** (소모품) | 즉시 성장 XP. 지급 규칙(한도 채우면 지급)·가격은 원본 그대로 |
| 빛나는 부적 (1개) | **[결정] 도색 공구 세트** (영구, 여러 개) | 전용기(이로치) 확률 단계별 영구 상승 — 아래 |
| 포켓몬 알 / 언커먼 알 / 레어 알 | 건프라 박스 / 언커먼 박스 / 레어 박스 (가칭) | 새로 시작 (등급 보증) |
| 민트 | **삭제** | (성격 시스템을 없애므로) |

**도색 공구 세트**
- **[결정]** 공구 세트는 성장 속도가 아니라 **전용기 확률**을 올린다. 한 번 사면 영구.
- **[제안]** 전용기 = 전용 컬러라서 도색 공구로 구성, 정해진 순서로 하나씩 구매:
  마스킹 테이프 → 먹선펜 → 도료 세트 → 에어브러시.
- **[제안]** 확률: 원본(기본 1/64, 부적 1/48)은 이로치가 덤일 때의 수치라, 전용기가 수집 대상인 이 게임엔 너무 낮다.
  기본 **1/32**, 공구 단계마다 1/26 → 1/21 → 1/16 → **1/12**.
- 가격은 빌더가 원본 부적 가격(3B)을 기준으로 단계별로 정한다.
- 특정 브랜드 제품명은 쓰지 않는다(상표).

## 6. 원본에서 걷어내거나 바꾸는 것

| 원본 기능 | 처리 | 근거 |
|---|---|---|
| PokéAPI 클라이언트 (`PokeAPIClient`, REST+GraphQL) | **삭제**, 내장 JSON 로더로 대체 | API 없음 |
| 런타임 스프라이트 다운로드·캐시 (`SpriteStore`) | 번들 리소스 로더로 대체 | 이미지 내장 |
| 포켓몬 이름 다국어 (`PokemonNameLocalization`) | 데이터 파일의 이름으로 대체 | |
| 진화 트리 `EvoNode` (분기 포함) | 기체별 **선형 등급 경로**로 단순화 | 등급 진화는 분기가 없음 |
| 성격(25종)·민트 | **[작성자 판단] 삭제** | 건담에 대응 개념 없음, 범위 축소 |
| 폼 시스템·안농 배지 (`PokemonForm`) | **[작성자 판단] 삭제** | 바리에이션은 별도 기체, 전용기는 이로치로 처리 |
| 메타몽 위장 이스터에그 | **[작성자 판단] 삭제** | 포켓몬 전용 |
| 프로필(타입·능력치·특성·기술) | **[작성자 판단]** 기체 프로필(형식번호, 소속, 등장 작품, 출시 등급 목록)로 교체 | 사실 정보만 |
| 지역 도감 (`PokedexRegion`, 도감번호 범위) | 작품 카테고리 (데이터 파일의 series 필드) | |
| 뒷모습 스프라이트 | **[작성자 판단] 삭제** (앞모습만) | 도트 작업량 절반 |
| UI 언어 8개 | **[작성자 판단] ko/en/ja 3개로 축소** | 새 용어 번역 부담. 기체 이름도 ko/en/ja |
| 후원(Sponsor) 링크·FUNDING.yml | **삭제** | 비상업 |
| 업데이트 확인·크래시 리포트 메일 등 원본 저장소를 가리키는 것 | 포크 저장소로 변경 | |

유지: 사용량 프로바이더 전부, 공식 한도, 비용, 메뉴바 항목, 플로팅 펫(크기·상호작용·말풍선), 기도/쓰다듬기 반응,
에이전트 활동 반응, 난이도 설정, 사탕(러너) 지급 규칙, 세이브 내보내기/가져오기/스냅샷, 로그인 시 실행.

## 7. 데이터

- 앱 번들에 `machines.json`(가칭) 하나. 원본 사용량 코드와 분리된 새 모듈에서 읽는다.
- 레코드당 필드 (최소):
  - `id` (안정 식별자, 세이브에 저장됨 — 한 번 정하면 바꾸지 않음)
  - `modelNumber` (예: RX-78-2), `names` {ko, en, ja}
  - `series` (첫 등장 작품 id, 하나), `faction` (연방/지온/…)
  - `rarity` (common/uncommon/rare/legendary) — 전용기도 자기 값
  - `grades`: 출시된 등급 배열 (순서는 SD→PG 고정 순서를 따름)
  - `gradeSources`: 등급마다 출시를 확인한 출처 URL (키트명 포함) — **[작성자 판단]** "없는 키트" 방지용
  - `variantOf`: 전용기면 기본기 `id` (이로치 관계)
  - `sprites`: SD 체형 / 리얼 체형 스프라이트 파일 이름
- **[작성자 판단]** 데이터 검증 스크립트를 둔다: 필수 필드, `id` 중복, `variantOf` 대상 존재, 모든 등급에 출처 존재,
  스프라이트 파일 존재(없으면 실루엣 경고) 등을 검사. CI에서 실행.
- **[작성자 판단]** 위키끼리 다르면 반다이 공식 상품 페이지(또는 Gunpla DB)를 우선한다.
- 작품 목록 `series.json`(가칭): `id`, `names`, 정렬 순서.
- 데이터 수집 출처: [Gunpla Wiki](https://gunpla.fandom.com/), [Gundam Wiki](https://gundam.fandom.com/),
  [Gunpla DB](https://www.gunpla101.com/), 일본어 위키백과 등급별 목록. 사실 정보만 옮긴다.

## 8. 스프라이트

- **[결정]** 오리지널 도트, 일정한 반복 움직임.
- **[제안]** 2~4프레임 반복 루프 (몸 들썩임, 모노아이/카메라아이 깜빡임, 버니어 불꽃 등).
- **[제안]** **SD·MGSD = SD 체형 도트 / HG~PG = 리얼 체형 도트**. 같은 체형 안의 등급 차이는 코드로 연출
  (크기, 테두리, 등급 배지, 오라·광택 효과). → 기체당 그림 2종 × 프레임 수.
- **[작성자 판단]** 형식: 원본 애니메이션 경로(GIF 디코딩)를 살릴 수 있게 **애니메이션 GIF**를 번들에 넣는다.
  빌더가 PNG 스프라이트 시트가 더 낫다고 판단하면 바꿔도 됨.
- **[작성자 판단]** 도트가 아직 없는 기체는 체형별 공용 실루엣으로 대체한다. 앱은 실루엣만으로도 완전히 동작해야 한다.
- 전용기(이로치)는 자기 스프라이트를 가진다(색만 다른 경우도 별도 파일).

## 9. 이름·저장소·배포

- **[작성자 판단]** 앱 이름 가칭 `MSTokenBar` — 「건담」「건프라」를 쓰지 않는다. 사용자가 바꿀 수 있음.

- 사용자 GitHub 계정에 포크, 로컬은 `~/Project/` 아래. `upstream` 리모트를 남겨 원본의 사용량 관련 수정을 가져올 수 있게 한다.
- 원본 LICENSE·저작권 표시 유지, README에 면책 문구.

## 10. 작업 덩어리와 순서

1. **앱** — 포크, 포켓몬 층 교체, 게임 규칙 구현. 기체 10~20개 정도의 소형 테스트 데이터 + 실루엣으로 동작 확인.
2. **데이터** — 첫 공개판 기체별로 출시 등급·이로치·레어도·작품·등급별 출처를 기록하고 검증 스크립트를 통과한다. [첫 공개판 명단](../../gunpla/initial-roster.md)
3. **도트** — 천천히. 체형별 2종 × 2~4프레임.

## 11. 빌더에게 맡기는 것

- 포켓몬 층을 걷어내는 구체적 순서와 파일 구조, 업스트림 병합을 쉽게 하기 위한 변경 격리 방법.
- 아이템·화면 문구의 최종 번역(ko/en/ja).
- 등급 연출 효과의 구체적 모양.
- 세이브 포맷 세부(원본 관대 디코딩 패턴 유지 권장).
- 테스트 구성(원본 테스트 중 포켓몬 전용 테스트 정리 포함).
- 뒷모습 스프라이트를 쓰던 반응(삐짐 등)의 대체 연출.
- 레어도별 출현 가중치의 구체 수치.
