# 후속 아이디어 메모

## 라이벌 전시와 전투 장면 배치

- **격납고 전시** — 라이벌 기체를 둘 다 모으면 격납고에 나란히 전시할 수 있다.
- **화면 배치** — 한 기체의 격납고 등급 칸을 모두 채우면 그 기체를 화면에 따로 꺼내 놓을 수 있다. 다른 기체를 키우는 동안에도 완성한 기체를 함께 전시할 수 있다.
- **전투 장면** — 화면에 배치할 수 있는 라이벌 두 기를 서로 마주 보게 놓아 작품 속 대결을 재현한다. 예를 들어 GP03 덴드로비움과 노이에 질, 또는 뉴 건담과 사자비를 한 쌍으로 놓는다.

## 실물 건프라로 발매된 확장 사양

기존 기체에 장갑·무장·지원기를 더해 외형이 달라지는 사양을 후속 스프라이트 후보로 모은다. 완성형 키트, 기본 키트에 동봉된 선택 장비, 별매 확장 세트 모두 대상이다. 후보를 추가할 때는 어떤 기체에 어떤 제품을 조합하는지 적고 실제 발매를 확인할 수 있는 상품 페이지나 설명서를 연결한다. 현재 제작 범위는 [첫 공개판 기체 명단](initial-roster.md)을 따른다.

## 클라우드 사용량 집계

- **문제** — 지금은 이 Mac에 남는 로컬 로그(`~/.claude/projects`, `~/.codex/sessions` 등)만 센다. Codex 클라우드 작업이나 Claude 웹·클라우드 세션처럼 서버에서 돈 사용량은 로그 파일이 생기지 않아 박스·기체 성장에 반영되지 않는다.
- **아이디어** — Claude와 Codex는 설정에서 계정을 연결하면 클라우드 사용량도 계정 쪽에서 가져와 합산한다. 계정을 연결하지 않으면 지금처럼 로컬 로그만 센다.
- **조사 결과 — Codex** (2026-11-24, Codex CLI 0.171.0) — `codex app-server`의 `account/usage/read`가 계정 기준 일별 토큰 합계(`dailyUsageBuckets`의 `startDate`·`tokens`)를 준다. [app-server 문서](https://learn.chatgpt.com/docs/app-server)에 실린 호출이고, 한도 조회(`account/rateLimits/read`)와 같은 연결·같은 Codex 로그인을 쓰므로 계정을 따로 연결하지 않아도 된다. 실제로 59일치를 받았고, 로컬 로그가 온전한 이틀은 로컬 합계와 0.1~0.3% 차이로 맞았다. 다만 하루에 숫자 하나뿐이라 모델, 토큰 종류, 기기, 실행 위치(로컬·클라우드)를 구분할 수 없고 비용도 추정할 수 없다. 클라우드 작업별 토큰을 주는 경로는 찾지 못했다(`codex cloud list`의 응답에도 토큰 값이 없다).
- **조사 결과 — Claude** (Claude Code 2.1.331) — 계정 기준 토큰 합계가 없다. 한도 조회(`/api/oauth/usage`)는 퍼센트와 추가 사용 금액만 준다. 클라우드 세션은 로컬과 같은 5시간·주간 한도를 쓰므로 퍼센트에는 이미 들어 있다. 토큰을 얻을 길은 Claude Code가 쓰는 세션 조회(`/v1/code/sessions`, `/v1/code/sessions/{id}/teleport-events`)뿐이고, 응답에 메시지별 토큰이 실리는지는 확인하지 못했다. 문서에 없는 경로라 예고 없이 바뀔 수 있다. claude.ai 일반 채팅의 토큰 수는 얻을 방법이 없다.
- **중복 없이 합치기** — Codex 계정 합계는 로컬 사용분까지 포함한 전체다. 그대로 더하면 두 번 세므로 날짜별로 「계정 합계 − 로컬 합계」만 더한다. 이 차이는 클라우드 사용량만이 아니다. 다른 Mac에서 쓴 양, 지워진 로그, 앱이 읽지 못한 로그(압축된 `.jsonl.zst`)가 모두 들어간다. Claude는 세션 이벤트가 로컬 로그와 같은 형식이면 지금의 메시지 ID 중복 제거를 그대로 쓸 수 있다.
- **순서 — 동기화 3단계 뒤** — 계정 합계는 기기를 구분하지 못한다. [여러 Mac 격납고 동기화](#여러-mac-격납고-동기화)가 격납고만 합치는 동안 Mac마다 「계정 합계 − 이 Mac의 로컬 합계」를 더하면, 다른 Mac에서 쓴 양이 그 Mac에서 한 번, 이 Mac에서 또 한 번 성장에 쓰인다. 하루에 회사 Mac이 1억, 개인 Mac이 1천만 토큰을 썼다면 두 Mac 모두 1.1억만큼 성장하고, 합친 격납고에는 실제 사용량의 두 배가 쌓인다. 3단계에서 Mac별·일자별 합계를 공유하면 「계정 합계 − 모든 Mac의 로컬 합계」로 어느 Mac에도 로그가 없는 양만 남길 수 있다. 그 양은 한 번만 반영해야 하므로 어느 Mac이 가져갔는지를 2단계의 기록 방식(먼저 도착한 기록을 인정)으로 남긴다. Claude 클라우드 세션도 두 Mac이 각자 가져오면 두 번 반영되므로 같은 기록이 필요하다.
- **동기화 3단계에 필요한 것** — 합계를 프로바이더별로 올린다. 계정 합계와 비교하려면 Codex 몫을 따로 알아야 한다. 날짜는 UTC 날짜나 시간 단위로 올린다. Codex 계정 쪽 날짜는 한국 날짜와 다르게 끊겨서(UTC 또는 미국 시간대로 보이며 문서에는 설명이 없다), 한국 날짜로만 합쳐 올리면 비교가 하루씩 어긋난다.
- **남은 확인** — Codex 계정 합계에 클라우드 작업이 들어가는지(계정 전체 집계라 가능성은 높지만 확인하지 못했다), 계정 쪽 날짜가 정확히 어느 시간대로 끊기는지, Claude 세션 이벤트에 토큰 수가 실리는지.

## macOS 위젯

- **문제** — 메뉴바에 다른 앱 아이콘이 많으면 MSTokenBar 아이콘이 가려져 팝오버를 열 수 없다.
- **아이디어** — 팝오버 홈 화면의 정보를 알림 센터·데스크톱 위젯으로도 보여준다. 작은 위젯은 현재 기체 그림, 등급(예: SD 1/6), 성장 막대, 오늘 토큰을 보여준다. 중간 위젯은 이번 주·이번 달 토큰과 비용, 연속 사용일을 더한다. 큰 위젯은 최근 14일 막대 차트와 다음 등급까지 남은 양까지 보여준다.
- **동작** — 앱이 사용량을 계산할 때마다 요약을 App Group 공유 폴더에 쓰고 위젯 새로고침을 요청한다. 위젯은 샌드박스 안에서 로그를 직접 읽을 수 없으므로 그 요약만 그린다. 위젯은 정지 화면이라 GIF 애니메이션은 쓰지 않고, 갱신 주기는 macOS가 조절하므로 팝오버보다 몇 분 늦을 수 있다.
- **확인할 것** — 위젯 확장은 샌드박스와 App Group 권한이 필요하다. Apple 개발자 계정 없이 자체 인증서(「MSTokenBar Local」)로 서명한 위젯이 다른 Mac의 위젯 갤러리에 뜨는지가 가장 큰 위험이다. 오늘 토큰만 보여주는 작은 위젯으로 시험판을 만들어 이 Mac과 다른 Mac에서 먼저 확인한다. 지금은 SwiftPM 빌드라 확장을 만들 Xcode 프로젝트나 번들 조립 스크립트가 필요하고, `release.sh`와 자체 업데이터도 확장이 든 앱 번들을 다루는지 확인한다.

## 여러 Mac 격납고 동기화

- **문제** — 토큰 사용량과 격납고는 각 Mac에 따로 쌓인다. 회사 Mac에서 만든 건프라가 개인 Mac 격납고에 보이지 않고, 반대도 마찬가지다. 설정의 세이브 내보내기·불러오기(`SaveTransfer`)는 기기를 옮길 때만 쓸 수 있고, 두 Mac을 함께 쓰는 경우는 해결하지 못한다.
- **1단계 범위 — 격납고만** — 기체별 보유 등급만 동기화하고, 모든 Mac의 보유 등급을 합집합으로 합쳐 보여준다. 격납고는 늘어나기만 하므로 동시에 써도 충돌이 없다. 성장 중인 건프라, 박스, 재화, 토큰 사용량은 Mac마다 따로 진행한다. 다른 Mac이 이미 완성한 등급을 이 Mac이 완성하면 기존 중복 획득 처리를 따른다.
- **저장소 — GitHub Gist** — 서버를 직접 운영하지 않는다. 설정의 「GitHub로 연결」에서 기기 코드 방식(device flow)으로 로그인하고 `gist` 권한만 요청한다. 토큰은 키체인에 보관한다. 동기화용 비밀 gist 하나에 Mac마다 `<기기 ID>.json`(보유 기체·등급 목록) 파일 하나만 쓰고 다른 Mac의 파일은 읽기만 하므로, 동시에 저장해도 서로 덮어쓰지 않는다. 비밀 gist는 주소를 알면 볼 수 있으므로 격납고 목록 외의 정보는 올리지 않는다. 저장소 소유자 계정으로 device flow를 켠 OAuth 앱을 한 번 등록해야 한다.
- **실패 처리** — 동기화에 실패하면 로컬 상태를 그대로 두고, 다음 동기화 때 자기 파일 전체를 다시 올린다. 파일이 항상 전체 목록이므로 별도 대기열이 필요 없다.
- **쓰지 않는 방식** — iCloud Drive와 CloudKit은 쓰지 않는다. 회사 Mac과 개인 Mac의 Apple ID가 다른 경우가 흔하고, CloudKit은 Apple 개발자 계정과 정식 서명도 필요하다. 자체 서버는 운영 비용과 계정 보안 부담이 커서 3단계에서 다시 검토한다.
- **이후 단계** — 2단계는 성장 진행도다. 진행도를 마지막 값으로 덮지 않고 Mac마다 늘어난 양을 기록으로 보내 더한다. 등급 완성·박스 개봉처럼 한 번만 일어나야 하는 사건은 먼저 도착한 기록을 인정하고, 늦은 Mac은 넘친 성장분을 다음 등급으로 넘기거나 먼저 열린 박스 결과로 맞춘다. 3단계는 토큰 사용량 합산과 계정이다. Mac별·일자별 합계만 올려 늦게 도착해도 그날 값만 갱신하며, 프롬프트나 경로는 올리지 않고 기본값은 꺼 둔다. 계정에서 가져오는 클라우드 사용량은 이 합계가 공유된 뒤에 붙인다([클라우드 사용량 집계](#클라우드-사용량-집계)의 순서 참고).
